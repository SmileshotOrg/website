## **3. Photo Organisation & Third-Party Cloud Storage Architecture**

- **Bring Your Own Storage (BYOS) Model:** SmileShot does not provide primary hosting, backup repositories, or cloud storage for raw clinical photography. All visual assets reside within the Subscriber's independently managed third-party cloud storage provider (e.g., Google Drive, Microsoft OneDrive, Dropbox). SmileShot acts strictly as an organizational cataloguing, indexing, and structuring interface.

- **Restricted Sandboxed Access ("SmileShot" Folder Only):** Upon account authorisation, the Subscriber grants SmileShot technical access strictly and exclusively to a single, designated root folder labelled **"SmileShot"** within their third-party cloud storage environment. SmileShot does not request, hold, or execute technical permissions to access, view, index, modify, or interact with any other files, folders, directories, or practice data outside this designated directory.

- **Metadata-Only Architecture & Technical Inability to View Imagery:** SmileShot is architected strictly as a metadata-level organisational interface. SmileShot’s platform infrastructure **lacks the technical capability, access permissions, and functionality to view, open, inspect, render, or visually process** the underlying image files or visual contents stored within the Subscriber's cloud repository. Platform operations are technically restricted solely to creating, reading, and managing directory pathways, folder naming structures, patient reference labels, timestamps, and indexing metadata necessary to structure the folder hierarchy on the Subscriber’s behalf.

- **Third-Party Storage Disclaimers:** The Subscriber is solely responsible for maintaining, provisioning, and securing their third-party cloud storage account, including storage quotas, subscription fees, and access credentials. Solid Solutions Ltd disclaims all liability for outages, downtime, data corruption, transmission latency, synchronization failures, or data loss occurring within or caused by the Subscriber's third-party storage environment.

- **Fair-Use & Indexing Quotas:** Subscription tier limits govern the volume of indexed patient profiles, active directory synchronisations, and API throughput processed through the platform, rather than raw gigabyte allocations on SmileShot servers. SmileShot reserves the right to monitor account usage patterns to ensure activity aligns with standard single-practitioner or single-practice operational volumes, and to restrict, throttle, or require a subscription tier adjustment for automated, scripted, or unauthorised multi-site access under a single account.

- **Statutory Classifications:**

- **Subscriber:** Data Controller for all Patient Identifiable Data (PID), clinical notes, and special category healthcare data.

- **Solid Solutions Ltd (trading as SmileShot):** Data Processor acting exclusively under the documented instructions of the Data Controller.

- **Data Processing Scope (Metadata Only):** Solid Solutions Ltd processes authentication credentials, third-party API authorization tokens, and administrative metadata (limited strictly to folder pathways, file directory names, patient reference identifiers, and timestamps within the designated "SmileShot" folder) solely to execute the Subscriber's organisational instructions.
